## JudgeAPI V2 三决策判定规则分析

梳理 `judge/next-action` 在什么情况下应返回 `ASK` / `COMPLETE` / `HANDOFF`，结论固化如下。

**判定顺序（有优先级的级联，不是三选一）**
1. 安全闸：输入不自洽 / 无未表达事项可问但不能完成 / 须人工处理的实体或程序事项 → `HANDOFF`
2. 完成闸：全部 `dispute_focus` 下各方均已表达五类要素 → `COMPLETE`
3. 推进闸：存在未表达的必要事项且可向一方提出 → `ASK`

**「充分表达」的判定口径**
每个 `dispute_focus` × 五类表达要素（主张、否认、请求、抗辩、证据证明目的）× 当事人。
关键规则：当事人一旦明确声称某项证据能证明某法律事实，即视为该事实表达完成，不得再追问证据内容/来源/形成过程/证明逻辑/充分程度/矛盾，但可转问其他未表达事项。

**硬门禁（schema 强制，非语义建议）**
- `decision` ∈ `allowed_actions`；`allowed_actions` 必须含 `HANDOFF`（安全阀不可关闭）
- `ASK` ⇔ `target != null`，且 `target` ∈ `allowed_targets`；`COMPLETE`/`HANDOFF` 的 `target` 必须为 `null`
- `HANDOFF` 的 `pending_points` 至少 1 项
- 请求侧：含 `ASK` 时 `allowed_targets` 必须非空

**权限收窄时的落位规则**
`allowed_actions` 不含 `ASK`（如已达询问轮次上限）：若焦点未表达完 → 只能 `HANDOFF`，不能 `COMPLETE`（`COMPLETE` 的实体门槛是"已充分表达"，不因轮次上限而降低）；焦点已表达完 → `COMPLETE`。

## 六步决策流程设计（18:06 补充）

用户要求详细阐述「最合理」的决策方式，固化为六步：0 输入预检 → 1 重建调查账本（争议焦点 × 双方 × 五要素状态表 + 从 role=JUDGE 记录提取已问问题与追问次数）→ 2 安全闸 HANDOFF → 3 完成闸 COMPLETE → 4 推进闸 ASK → 5 输出自检。

级联而非平行打分的理由：HANDOFF 错误成本最低（不推进流程）且是唯一安全出口；COMPLETE 不可逆须高门槛；ASK 是默认推进但模型有「继续提问」的惯性偏差，必须放在完成闸之后防「为问而问」。

新增发现：
1. `next_action_service.py` 调用 `runner.execute(preserve_context=True)`，与协议「每次调用无服务端会话记忆」存在张力，若 preserve_context 指跨调用会话记忆，会破坏决策独立性，需核实语义。
2. agent 配置 `max_output_tokens=2048`，而 `speech` 上限 4000 码点，COMPLETE 中文总结 + JSON 结构可能超限导致截断 → 502，建议提到 ≥4096。
3. 轮次上限的唯一信号是 `allowed_actions` 不含 ASK，模型不得自行维护轮次计数。

## 发现的契约/实现不一致（待处理）

1. `app/api/integrations/virtual_court/PROTOCOL_V2.md` 是旧版，仍把 `/judge/law-check` 描述为当前接口，与 `D:\project\VirtualCourt\Docs\judge_protocol_v2.md`（2026-09-16，已废弃 law-check）冲突，需同步。
2. 代码侧仍暴露已废弃能力：`judge.py` 注册了 `POST /judge/law-check` 路由；`schemas/.../judge.py` 保留 `JudgeLawCheckRequestV2`/`ResponseV2` 与 `NO_ACTION`/`EXPLAIN_LAW`。建议加废弃标记或下线，避免 VirtualCourt 误用。
3. `JudgeRecord.role` 是自由字符串（≤64 码点），而 `allowed_targets` 用 `PartyRole` 枚举（仅 `PLAINTIFF`/`DEFENDANT`）。→ 法官既往提问可作为 `role="JUDGE"` 的 `SPEECH` 记录传入；VirtualCourt 必须回传既往问与答，否则提示词里"避免重复询问"无法执行。
4. `pending_points` 在 `ASK` 下的语义未定义（schema 不限制，协议只要求 `HANDOFF` ≥1 项），建议明确为"后续仍需调查的点"或要求 `ASK` 时为空数组。
5. `records` 中 `SUMMARY` 记录（`role` 必须为 `null`）的出现时机未明确：理论上上次 `COMPLETE` 后不会再进入调查循环，需与 VirtualCourt 确认。
